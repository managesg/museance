# Before and after repair

Generated by `eval/before_after.py` from committed evidence only (`cases/<app>/repairs.jsonl`, `cases/<app>/regression-result.json` and its git history, `cases/*.case.yml`, commit subjects). A value missing from every committed file is `null` in the JSON and `not recorded` here; nothing is estimated.

## JSON shape (`cases/before_after.json`)

`{"rows": [ ... ]}`: one flat row per app and revival version. Keys: `app`, `version` (v1 = first revival), `sha256`, `regression_passed`, `regression_total`, `attack_mismatches`, `traps_flagged`, `traps_of`, `false_strikes`, `false_strikes_of`, `fidelity`, `repair_claim`, `repair_decision`, `repair_builder`, `repair_reason`, `repair_to` (the repair that produced the next version; null on the last version), `not_recorded` (keys that are null because no committed file has them).

`traps_flagged` = trap behaviors where the revival diverged from the original, i.e. traps the court caught. Fewer after repair means the revival now matches the original on them, not that the court got worse.
