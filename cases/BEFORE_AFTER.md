# Before and after repair

Generated by `eval/before_after.py` from committed evidence only (`cases/<app>/repairs.jsonl`, `cases/<app>/regression-result.json` and its git history, `cases/*.case.yml`, commit subjects). A value missing from every committed file is `null` in the JSON and `not recorded` here; nothing is estimated.

## JSON shape (`cases/before_after.json`)

`{"rows": [ ... ]}`: one flat row per app and revival version. Keys: `app`, `version` (v1 = first revival), `sha256`, `regression_passed`, `regression_total`, `attack_mismatches`, `traps_flagged`, `traps_of`, `false_strikes`, `false_strikes_of`, `fidelity`, `repair_claim`, `repair_decision`, `repair_builder`, `repair_builder_source` (commit or file that proves the builder), `repair_reason`, `alternate_of` (only on a row for a different builder's repair of an earlier version), `repair_to` (the repair that produced the next version; null on the last version), `not_recorded` (keys that are null because no committed file has them).

`traps_flagged` = trap behaviors where the revival diverged from the original, i.e. traps the court caught. Fewer after repair means the revival now matches the original on them, not that the court got worse.

Fidelity differs by source: todo v1 shows 35 because it is read from `repairs.jsonl`, which scores attacks only; the todo case file at 9a5877c shows 36 because it scores claims plus attacks.
