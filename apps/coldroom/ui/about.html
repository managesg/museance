How it works

Prove the patch changes nothing but the hole.

MUSÉANCE puts a patched building controller on trial against the legacy one it replaces. A deterministic court, with no AI in it, replays identical tests on both. Cooling behavior must match. Attacks must only work on the original.

Why this exists

The problem is real, and the hard part is trust, not code.

The attacks

On 11 Oct 2026, refrigeration controllers at up to about 700 French supermarkets were switched into defrost overnight. A second wave on 2 Nov reached about 10 more European countries. Food was thrown out. Danfoss said its products were involved.

The trap

Much of this controller software is end of life: no vendor patches, write commands with no authentication. You can rebuild or patch it yourself, but an unverified patch is a new risk. Did you just change how the fridge cools?

The answer

Run the old controller and the patched one side by side on identical inputs, compare what they do, and keep a tamper-evident record. Only measured results count.

The pieces

Everything runs on one laptop, on 127.0.0.1, started with one command.

Controllers

apps/coldroom/controller.py. One model, a --patched flag. HTTP contract: GET /state, POST /setpoint, /defrost, /tick, /reset. Simulated time, 1 tick = 60 s, no wall clock.

Court

court/coldroom.py. Replays the docket on both builds, decides every verdict by comparing text, locks results with the Bailiff, chains everything into ledger.jsonl.

Dashboard

Reads live state every second, runs the clock, sends attacks to both builds, flips court cards from real verdicts. Falls back to a built-in simulation if the backend is down, and says so.

How the court decides, without AI

A claim is a test, not an opinion. The court runs it and reads the result.

  1. Reset both builds to the same starting state (for example: room at setpoint + 1.2 °C).
  2. Replay the exact same steps on the ORIGINAL and the PATCHED controller: writes, ticks of simulated time, reads.
  3. Do it twice per build. Four readings per test.
  4. Compare text. That is the whole decision, so the same inputs always give the same verdict.

Did the two runs on one build agree?run 1 == run 2UNSWORN if not. Never STRUCK: the court would rather say "unknown" than accuse.

Does the patch behave the same?original == patchedMATCH for control tests. For attacks the builds must differ: PATCH WORKS.

The docket: 6 behaviors and 2 attacks

Tests are relative to each unit's setpoint, so the same docket works for a 4 °C dairy room and a -20 °C freezer.

IdBehaviorMust
c1Compressor turns on above setpoint + 1 °CMATCH

c3High-temp alarm fires only after 10 minutes above setpoint + 4 °CMATCH
c4Defrost every 6 h for exactly 20 minutes (compressor off, alarm suppressed)MATCH
c5No alarm during 12 h of normal coolingMATCH
c6Room recovers to setpoint + 1 °C after a defrostMATCH
sec-setpointUnauthenticated write: setpoint to 25.0 °CDIFFER
sec-defrostUnauthenticated write: defrost from 20 min to 8 hDIFFER
Why the alarm stays silent on the original. The alarm compares against the setpoint. Once an attacker moves the setpoint to 25 °C, the alarm only fires at 29 °C, so the room warms with nothing complaining. Long defrost suppresses the alarm for hours. This is what our model shows; we do not claim the real attacks disabled alarms.

The patch, in full

Two lines in court/coldroom.py. Nothing else changes, and the court proves it.

# write_setpoint
if self.patched and (str(pin) != PIN or not self.prof["lo"] <= float(value) <= self.prof["hi"]):  # PATCH
    return {"ok": False, "msg": "write rejected: unlock required + out of range"}
# write_defrost
if self.patched and (str(pin) != PIN or int(minutes) > 20):  # PATCH
    return {"ok": False, "msg": "write rejected: unlock required + max 20 min"}

A record nobody can quietly rewrite

Every test is committed before the trial, every verdict after, each linked to the one before.

Hash chain

Each ledger event stores hash = sha256(prev_hash + payload). Change one character anywhere and every later hash breaks. python -m court.ledger verify runs/coldroom/ledger.jsonl names the first broken link.

Commit first

The tests and attacks are hashed into the ledger before the court runs, so nobody can tune a test after seeing the result. The dashboard's ledger chip shows the head of this chain.

Honest scope

  • The store and its controllers are modeled: fictional FreshMart, not vendor code, no real controller models named.
  • Time is simulated (1 tick = 60 s), so a 12-hour test runs in about a second and is fully reproducible.
  • The court proves equivalence to the original model. A real deployment needs a faithful emulator or test bench of the actual controller; never point the court at live equipment.
  • Next step: the real end-of-life PLC runtime OpenPLC_v3 (archived, default credentials), run in a sandbox.
